# Standing project execution rules

These requirements apply to subsequent OTTO project work, as directed by the owner
on September 10, 2026. Necessary work in the already authorized services may continue
without repeated permission requests. Renewed service authorization must be requested
only when genuinely required.

## Operating loop

Research → hypothesis → implementation → tests → bounded experiment → inspect →
decide → durable checkpoint → report → continue.

Before paid or lengthy runs verify code with a smoke test, input schemas and hashes,
artifact availability, restart behavior, explicit resource/time caps, and a decision
rule. Use smoke, small sample, single temporal window and representative validation
before full scale. Diagnose failures before another launch. Stop clearly inferior,
duplicated or methodologically invalid directions promptly. Persist successful work
with checksums and UTC heartbeats, stage timings and progress counters.

## Feature evidence

Feature engineering remains open until major realistic, valuable avenues have a
measured decision or a concrete data-based exclusion. Deferred work remains open.
Research domain mechanisms, strong competition implementations, academic approaches,
statistical representations and usable external data. Anonymous IDs do not supply
missing product semantics or customer identities.

For each family document its rationale, information availability and leakage
assumptions, implementation, explicit tests, fitting-only screening, contribution,
ablation, and temporal stability. Feature counts alone do not establish quality.
Preserve negative findings. Previously inspected cohorts cannot become untouched
tests. Use official pooled weighted Recall@20 and each objective, and distinguish
retrieval coverage from achieved ranking. Competition, selection and evaluation
scores must remain clearly separate.

## Milestone review

Report what was attempted, what actually completed, what passed, what failed or
underperformed, exact results, saved artifacts/checkpoints, GitHub status, lessons,
the next highest-value step, and why it merits more compute. Activity alone is not
progress. Record source and result commits, pull requests and merges. Keep canonical
notebook names, publish executed outputs, and make employer-facing claims match
verified evidence.

The target is the strongest realistically attainable performance, with the historical
leader treated as a research target rather than a guaranteed outcome. Favor useful
information per experiment, reliable recovery, methodological validity, restrained
compute spending, and a polished employer-facing repository.
