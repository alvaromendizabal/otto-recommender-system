# Run the synthetic recommendation demo

Run a complete, small recommendation pipeline locally with **Python 3.11 or later**.
It uses only the standard library: no installation, account, data download, GPU or
cloud service is required.

From the repository root:

```bash
python3 -S scripts/run_public_demo.py --output /tmp/otto-public-demo
python3 -S scripts/run_public_demo.py --output /tmp/otto-public-demo --check
```

Open `/tmp/otto-public-demo/report.html` in a browser. The report works offline;
all styles, interactions and example data are included in that one file. Use the
session and objective selectors to inspect clicks, carts and orders. Keyboard
navigation, visible focus states, labeled controls and a mobile layout are included.

**Everything generated by this demo is synthetic.** Its scores illustrate a working
evaluation contract. They are separate from the published temporal study and scored
release, and do not reproduce the private research or inference system.

## What actually runs

| Stage | Inputs | Result |
| --- | --- | --- |
| Generate | A fixed seed and small public configuration | Synthetic historical sessions, observed query prefixes and separate future targets |
| Fit | Historical events only | Transparent co-occurrence and objective-specific popularity statistics |
| Predict | Fitted source statistics and observed prefixes | Retrieved candidates, objective-specific top-20 lists and source-only score explanations |
| Seal | Completed prediction records | A prediction artifact with a SHA-256 identity |
| Evaluate | Sealed predictions and synthetic future targets | Pooled objective recalls and a separate candidate-coverage ceiling |

The demonstration combines historical co-occurrence, observed-prefix recency and
historical popularity. It uses a deliberately simple, inspectable scoring rule.
For each objective it scores the 120-item synthetic catalog, retains 50 candidates
and returns the first 20. This small example illustrates the contracts; its exhaustive
catalog scoring is not the large-scale retrieval implementation.
Item IDs are anonymous synthetic identifiers; the report does not invent product
names, shopper identities or semantic descriptions.

The report shows actual component values and sources for each recommendation.
Future target items appear in a separate, initially closed evaluation panel. This
makes it possible to distinguish an item that retrieval missed from an item that
was retrieved but ranked below the final twenty.

## Read the metrics correctly

For each objective, pooled Recall@20 is:

$$
\mathrm{Recall@20} =
\frac{\sum_s |\mathrm{Top20}_s \cap \mathrm{Targets}_s|}
{\sum_s \min(20, |\mathrm{Targets}_s|)}
$$

The weighted metric combines **10% clicks, 30% carts and 60% orders**. It is not the
unweighted average of session-level recalls.

The candidate oracle uses the same denominator, counting target items present
anywhere in the retrieved pool and capping each session's hits at twenty. It is a
coverage ceiling, not achieved ranking quality. The report labels both values as
synthetic and displays objective-level hit counts and denominators alongside them.

Aggregate metrics use every generated query. The session explorer displays a small
set of example queries, not a separate benchmark or a cherry-picked performance
claim.

## Inspect the artifacts

| File | Contents |
| --- | --- |
| `report.html` | Self-contained interactive walkthrough, objective metrics, examples and provenance |
| `predictions.json` | Sealed candidate lists, recommendations and inference-time explanations |
| `result.json` | Synthetic run configuration, metrics, example evaluations, stage status and identities |
| `manifest.json` | Demo ownership, configuration, implementation identity and artifact sizes and SHA-256 hashes |

Run the first command again to verify and reuse a completed matching run. `--check`
verifies existing artifacts without fitting or rewriting them. Changed artifact
bytes, a different seed or an incompatible implementation fail verification.
The runner refuses to overwrite unrelated files in the chosen output directory.

To generate another deterministic example, use a new directory and pass the same
seed to generation and checking:

```bash
python3 -S scripts/run_public_demo.py --seed 7 --output /tmp/otto-public-demo-seed7
python3 -S scripts/run_public_demo.py --seed 7 --output /tmp/otto-public-demo-seed7 --check
```

Checksums make accidental artifact changes detectable. The public tests also check
information boundaries, metric arithmetic, deterministic replay and recovery from
interrupted output creation.

GitHub Actions runs the same dependency-free tests, generation, reuse and verification
in the [Public synthetic demo workflow](../.github/workflows/public-demo.yml). A successful
run publishes the `public-synthetic-demo` artifact containing the report and its JSON
receipts for download from the workflow run.
